## THE SOLUTION: DOORWAY

Doorway is the **harness layer** that makes all AI coding tools reliable.

### What It Provides

1. **Memory** — Remembers everything, learns patterns, gets smarter over time
2. **Visibility** — See what tools did, why they failed, what files changed
3. **Orchestration** — Coordinates Claude Code + Codex + Cursor seamlessly
4. **Evidence** — Full audit trail for compliance
5. **Self-Evolution** — Improves itself from observed patterns

## THE 7-BREAKTHROUGH DETAIL

```
┌────────────────────────────────────────────────────────────────────────────┐
│                    THE 7 BREAKTHROUGH FEATURES                           │
└────────────────────────────────────────────────────────────────────────────┘

1. CROSS-MODEL THREADING
─────────────────────────
   Thread: "Build login with OAuth + tests + docs"

   Step 1: Claude Opus ──► Auth logic (complex reasoning)
        ↓
   Step 2: Codex ──► Tests (fast, accurate)
        ↓
   Step 3: Cursor ──► Inline polish (best autocomplete)
        ↓
   Step 4: Playwright ──► Browser proof (visual verification)
        ↓
   Step 5: Claude ──► Code review (final check)

   User sees ONE THREAD with ALL progress visible.

2. VISIBLE PROCESS TREE
────────────────────────
   Codex shows:
   "Running pnpm test..."
   ✅ Tests passed

   Doorway shows:
   Process Tree:
   ├── node pnpm.js test ──► Running
   │     ├── node eslint.js ──► ✓ (2.1s)
   │     ├── node jest.js ──► ✓ (15.3s)
   │     └── node coverage.js ──► ⚠️ SIGKILL (8.2s)
   │           └── OOM: Jest worker killed, exceeded 512MB

   Files Changed:
   + src/auth/oauth.ts (created)
   ~ src/auth/login.ts (modified)

   💡 Suggestion: Increase --max-old-space-size=1024

3. PERSISTENT WORKFLOW MEMORY
──────────────────────────────
   Remembers:
   • Project context (tech stack, conventions, patterns)
   • Session history (files touched, errors seen, decisions made)
   • User preferences (tool choices, workflow style)
   • Learned patterns (what works, what fails, what to avoid)
   • Cross-project learnings (shared knowledge)

   Gets smarter every session.

4. EXIT CODE TAXONOMY
─────────────────────
   SIGSEGV (11)     = Segmentation fault (memory corruption)
   SIGKILL (9)      = OOM killed / timeout
   SIGABRT (6)      = Assert failed / panic
   SIGFPE (8)       = Floating point exception
   127              = Command not found
   1                = General error (analyze output)
   2                = Usage error

   Context matters. Exit codes are meaningful.

5. SESSION REPLAY + EVIDENCE
─────────────────────────────
   Full audit trail:
   • Timeline of every action
   • Screenshot at each step
   • Full diff of every file change
   • Terminal output (PTY recording)
   • Process tree snapshots
   • Export for compliance

   Enterprise-ready. Audit-ready.

6. SELF-EVOLVING HARNESS
─────────────────────────
   Doorway watches itself:
   • Track success/failure patterns
   • Learn which models work best for which tasks
   • Propose workflow improvements
   • Auto-tune parameters for success
   • Safe apply: test in worktree before committing

   The harness gets better over time.

7. ENTERPRISE GOVERNANCE
──────────────────────────
   • Audit trails (who did what when)
   • RBAC permissions (role-based access)
   • EU AI Act compliance
   • SOC2 support
   • BYOK for API keys
   • SSO integration

   Enterprises can use it.
```
